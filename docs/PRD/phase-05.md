# Phase 5 PRD — 進階強化（Enhancement）

> 目標：補上「聽得到的和弦」與「看得到的累積」——和弦合成示範音、練習統計儀表板、自訂進行編輯器，並做整體體驗打磨。
> 結束狀態：RCS 成為完整閉環：練（三條線）→ 聽（示範音）→ 看見進步（統計）→ 自造教材（自訂進行）。

## 1. 範圍

### In scope
- Web Audio 和弦合成示範音（接進和弦線跟練）
- 練習統計儀表板（吃 Phase 2 起累積的 practiceLog）
- 自訂進行編輯器（級數輸入 → 跟練）
- 體驗打磨：鍵盤快捷鍵、無障礙、效能、錯誤回報
- 設定匯出/匯入（JSON 檔，含自訂 pattern/進行與練習日誌備份）

### Out of scope（保持未來擴充清單）
- 帳號/雲端、麥克風判定、採樣音源、左手模式、自訂調弦、淺色主題、PWA

## 2. 功能需求

### F5-1 和弦合成示範音
1. 合成器：多音 OscillatorNode（三角波/鋸齒混合 + lowpass + ADSR），模擬撥彈即可，不追求擬真吉他音。
2. 發聲模式（和弦線跟練頁可選）：
   - `off`：維持純 click（預設，尊重「click 為主」原則）
   - `pad`：每次和弦切換時輕聲鋪底全小節
   - `strum`：每小節第 1 拍模擬掃弦（音符 10–20ms 錯開）
3. Voicing 策略：中音域 close voicing（root 3rd 7th 優先），聲部連接就近移動——由 theory 引擎給音、audio 層只管發聲。
4. 音量獨立於 click，混音不蓋拍點；行動裝置效能驗證（複音數上限 6）。

### F5-2 練習統計儀表板
1. 總覽卡：本週練習時長、連續練習天數（streak）、累計時長。
2. 圖表：近 4 週每日練習時長長條圖（依三條線分色堆疊）；各模組時長佔比。
3. 明細：練習日誌列表（日期、模組、時長、BPM），可依線別篩選。
4. BPM 進步線：同一模組＋同參數的歷史 BPM 折線（例：16 分 FUNK pattern 從 80 → 100 的軌跡）。
5. 資料管理：清除紀錄（需確認）、匯出 JSON。

### F5-3 自訂進行編輯器
1. 輸入：級數記法文字（沿用 F3-2 parser，白名單文法 + 即時錯誤提示），或在五度圈上點選和弦逐一加入。
2. 設定：每和弦小節數、BPM、（可選）12 調循環開關。
3. 預覽：展開為和弦序列（任選調試看），存入 localStorage 後出現在和弦線模組列表，跟練體驗與內建 preset 完全相同（含指板同步、五度圈 highlight）。
4. 管理：改名、複製、刪除、匯出/匯入。

### F5-4 體驗打磨
1. **鍵盤快捷鍵**：space 播放/停止、↑↓ 調 BPM（±1 / shift±10）、← → 換 preset；快捷鍵說明面板（`?`）。
2. **無障礙**：全站鍵盤可達、SVG 組件 aria 標籤、色彩對比複核；`prefers-reduced-motion` 時脈衝改為非動畫高亮。
3. **效能**：指板/五度圈/節奏譜渲染 profiling（60fps 目標）；首屏 bundle 分包（練習模組 lazy load）。
4. **穩定性**：全域 error boundary + localStorage 損毀自復原（備援預設值）；版本 migration 實測。

## 3. 驗收標準（Phase DoD）
- [x] 和弦示範音三模式可切換，開啟後 click 拍點依然清晰可辨（pad 低通 700Hz vs click 1kHz+）；
      複音數硬夾在 6
- [x] 儀表板正確反映歷史日誌（舊日誌 schema 未變，無需 migration；設定 v2→v3 附 migration 與測試）
- [x] 自訂進行：建立 → 跟練 → 匯出 → 匯入還原，全流程可用（瀏覽器實測）
- [x] 快捷鍵與 a11y 檢核通過：六條路由的文字對比全數達 AA、五度圈可用鍵盤操作、
      快捷鍵在文字輸入框內不攔截
- [x] 全站 bundle：首屏 < 200KB gz

### 本 Phase 的實作決策（補充規格）
1. **彈哪幾個音是樂理，怎麼發聲是音訊**：`core/theory/voicing.ts` 決定聲位
   （中音域 close voicing、取捨優先序 1→3/4→7→最高延伸音→其餘→5、自動挑移動距離最小的轉位），
   `core/audio/chordVoice.ts` 只把 MIDI 音高變成聲音。兩層都能單獨測。
2. **示範音走 `subscribeSchedule` 而不是 `subscribeTick`**：視覺 tick 是在 audioTime 已經到達時
   才觸發的，那時才排程等於晚半幀。因此 transport store 分成兩種訂閱，契約寫在檔案頂部。
3. **示範音預設 off**：click 才是主角；升級舊使用者不該突然多出聲音。
4. **統計不是練習模組**：沒有 click、不寫日誌、不掛 TransportBar，所以走獨立路由 `/stats`
   而不是進模組註冊表。
5. **統計以使用者的日曆天分組，不是 UTC 天**：跨時區時 UTC 會把晚上 9 點的練習算到隔天，
   連續天數就斷了。「今天還沒練」不算斷——連續紀錄從今天或昨天起算。
6. **BPM 折線一天取當天最高值**：同一天練三輪不該畫成三個點，而「那天撐到多快」才是進步。
   y 軸不從 0 起算，否則 80→100 是一條平線。
7. **備份原封不動搬 envelope**：含各 store 自己的 version，讀取時照走 VersionedStore 的
   migration 鏈，所以舊備份檔自動升級，備份層完全不需要認識任何 schema。
8. **自訂進行是獨立模組（`chords.custom`）**，不是塞進既有兩個和弦模組的 preset 清單：
   它多了一整套編輯與管理，塞進去會讓那兩個模組同時是練習器又是編輯器。
   資料模型的 `barsPerChord` 是單一數字而不是每個和弦一個值——手打時維護等長陣列只會出錯。
9. **記法解析不過就整頁停用跟練**，不拿壞資料去排程；錯誤訊息不轉發 core 的英文例外，
   只取 `tokenIndex` 配自己的 i18n 說明與範例。
10. **快捷鍵在文字輸入框內一律不攔**：自訂進行編輯器要打得出 `ii V I`，
    空白鍵若被當成播放鍵那個功能就廢了。這是正確性不是體貼。
    另一條對稱規則：沒處理掉的鍵不 `preventDefault`，← → 在沒註冊 preset 清單的頁面
    保留瀏覽器原本的捲動。
11. **文字對比複核的結論是「把 ink-500/600 退為結構色」**：兩者在面板上只有 3.5:1 與 1.9:1，
    不到 AA 的 4.5:1。層次改由字級、字重與 mono 與否表達，不再靠把文字調暗。
    詳見 design-system.md §2。
12. **兩層 i18n 防線**：`app.spec` 用 vue-i18n 的 missing hook 逐路由掃描（漏翻會在畫面上
    印出 key，建置與 typecheck 都抓不到），`locales.spec` 檢查兩語系 key 一致、無空字串、
    插值變數一致。這次真的漏了整個 `custom` 區塊才發現原本沒人守。

## 4. 風險
| 風險 | 對策 |
|---|---|
| 合成和弦音在手機喇叭上糊掉蓋住 click | click 頻段（1kHz+）與 pad 頻段（lowpass < 800Hz）錯開；strum 模式預設音量低 |
| 統計圖表拉入重量級圖表庫破壞 bundle 目標 | 自繪 SVG 長條/折線（資料量小，不需要圖表庫） |
| 自訂進行 parser 錯誤訊息不友善 | 即時逐 token 驗證 + 錯誤位置高亮 + 範例提示 |
