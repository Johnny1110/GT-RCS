# Phase 7 PRD — 指板回想（Fretboard Recall）

> 目標：關上「回想」這個閉環。前六個 Phase 蓋的是**顯示器**——畫面永遠先給答案，
> 使用者練的是「辨認」。但台上需要的是「產出」，兩者在腦裡是不同的路徑。
> 本 Phase 把答案藏起來再問，讓指板從看得懂變成想得起來。
>
> 結束狀態：音階線多一個模組，同一塊指板既能顯示也能出題；
> 它是之後「弱點排程（SRS）」與「耳朵訓練線」的作答介面雛型。

## 1. 範圍

### In scope
- 指板回想模組（`scales.recall`，路由 `/scales/recall`）：兩個方向 × 兩種語言 = 四種練法
- Fretboard 組件的互動能力：整塊指板可點、可畫空心標記（純轉發，不含樂理）
- 節拍驅動出題（click 每 N 小節換一題）——回想要在時間壓力下才算數
- 本輪計分（題數／命中／誤點／正確率）與誤點回饋（「那是 D，不是 C#」）

### Out of scope（列入後續）
- **調內和弦反查**（「Eb 調的 vi 是什麼、第 5 弦根音在哪」）——它屬於和弦線，不是音階線
- **弱點排程（SRS）**：本 Phase 只產生作答結果，不做間隔重複排程。
  per-item 統計的 schema 留給 SRS 模組定義，這裡不先猜
- 麥克風判定（你點對了，但你真的彈得出來嗎）、視奏、自訂調弦

## 2. 功能需求

### F7-1 兩個方向 × 兩種語言

「方向」與「語言」是兩個正交的設定，四種組合共用同一套機制與計分：

| | 語言＝音名 | 語言＝度數 |
|---|---|---|
| **方向＝找位置** | 找出全指板所有的 C# | 在 A dorian 找出所有的 b3 |
| **方向＝說名字** | 這一格是什麼音？ | 這一格在 A dorian 是幾度？ |

1. **出題池**：音名用 `modules/scales/shared.ts` 的 `KEYS`（12 個標準拼寫，含 F# 與 Db）；
   度數用 `spell(root, SCALE_FORMULAS[scale])` 推導的音階內度數。**畫面不得 hardcode 任何音名**。
2. **找位置**：指板一開始全空，點對一格就亮出那個音點（帶正確的度數顏色與標記——
   答對本身就是教學）；點錯不亮，但回饋列說出你點的是什麼。全部找到＝該題完成。
3. **說名字**：指板上一格畫白色空心圈（不帶標記），下方列出選項；
   度數語言時選項＝該音階的度數，音名語言時選項＝12 個標準拼寫。
   答案一律**以 pitch class 比對**——按到 F# 而心裡想 Gb 也算對。
4. **顏色錨點**：度數語言以 root 為錨（找到的音點顯示真實度數色）；
   音名語言以該題目標音為錨（找到的都是白色主音點，標記顯示音名）。

### F7-2 節拍驅動出題
1. `每題小節數`：`0`（不限時，答完才換）／`2`／`4`／`8`。預設 `0`。
2. 非 `0` 時由 **Transport 的小節數**換題，不用 `setInterval` 也不用牆上時鐘
   （反模式清單第 2 條）；沒按播放就不會換題，畫面明說這件事。
3. 換題時把上一題的結果推進回饋列（「上一題 C#：找到 8/11」），沒找到的計入漏掉。

### F7-3 計分與回饋
1. 本輪統計：題數、命中格數、漏掉格數、誤點次數、正確率。換調／換音階／換模式即歸零。
2. 誤點回饋分兩種，都要說得出所以然：
   - 音名語言：`那是 D`
   - 度數語言：在音階內 → `那是 2`；不在音階內 → `D 不在 A dorian 裡`
3. 練習時長沿用 `usePracticeSession`（play 起算、stop 結算），與其他模組完全一致。

### F7-4 Fretboard 組件的互動能力
1. 新增 `selectable`：在每一格（含沒有音點的格）畫透明命中區，emit `fretClick({string, fret})`。
   組件**只轉發座標**，對錯與計分一律在模組層。
2. 新增 `marks`：在指定座標畫 `ink-50` 空心圈（說名字方向的題目）。
3. `FretCell` 抽出 `FretPosition`（`{ string, fret }`）作為基底型別——
   指板座標與「座標上有什麼音」是兩件事，回想測驗需要前者而不需要後者。

## 3. 驗收標準（Phase DoD）

- [ ] 四種組合都能出題、作答、計分；12 個調 × 12 個音階都不丟例外
- [ ] 出題池與答案位置全部由 `core/theory` 推導；模組內零 hardcode 音名（測試鎖定）
- [ ] 限時模式的換題由 transport 小節數驅動；模組內無 `setInterval` / `Date.now()` 參與換題
- [ ] `npm run test` 綠燈，`quiz.ts` 有純函式測試（出題池、答案位置、洗牌不連續重複、比對）
- [ ] `npm run typecheck` 零錯誤；依賴規則零違規（Fretboard 仍是 presentational）
- [ ] 兩個 locale 檔同步；`config/routes.ts` 補上新路由（漂移守門測試會擋）
- [ ] `npm run build` 成功，首屏 bundle 未成長（模組 lazy load）

### 本 Phase 的實作決策（補充規格）

1. **歸在音階線，不另開第四條線**：第四條線留給耳朵訓練（backlog 排序第一）。
   指板回想的核心是「音階內的音在哪」，屬於音階線的延伸。
2. **方向與語言是兩個正交設定，不是四個模式列表**：四選一的清單會讓使用者
   以為它們是四個不同的練習；兩個開關才看得出「同一件事的兩個方向」。
3. **不做碼表**。限時模式的時間感由 click 與拍燈給（`Click 是全站心臟`），
   不限時模式在答完時才報用時。再加一個自走的計時迴圈只會多一條與 tick 不同步的時間線。
4. **答案以 pitch class 比對，不比拼寫**。F# 與 Gb 在指板上是同一格；
   要求使用者猜對拼寫是在考另一件事，會把回想測驗變成拼寫測驗。
5. **點錯要說出你點的是什麼**。只說「錯」沒有教學價值；
   「那是 D」讓使用者當場修正自己的心智地圖。這是本模組真正的產出。
6. **命中區蓋在最上層，只在 `selectable` 時存在**。把位框與音點的既有點擊行為
   在回想模式下用不到，兩者不會互搶事件。
7. **找到的音點用真實度數色**，不是統一的「正確綠」。答對的獎勵就是那個顏色——
   它同時強化了全站的 12 色 mapping，而綠色是 `2` 度的顏色，拿來當狀態色會污染色彩系統。

## 4. 風險

| 風險 | 對策 |
|---|---|
| 找位置方向對鍵盤使用者不可用（6×23 個命中區不可能都給 tab 停留） | **說名字**方向全鍵盤可達，是等價的替代練法；不加 138 個 tab 停留（那比沒有更糟）。列為已知限制 |
| 22 格 × 6 弦的命中區在手機上太小 | 命中半徑取音點半徑的 1.4 倍（格寬 42px 下約 30px）；指板本來就可橫向捲動 |
| 限時模式沒按播放看起來像壞掉 | 畫面明說「限時模式要按播放，click 會替你換題」，且預設是不限時 |
| 出題池在五聲音階只有 5 個度數，很快就重複 | 洗牌發牌（發完一副才重洗），至少保證同一輪內不重複；連續兩題不同項目 |
